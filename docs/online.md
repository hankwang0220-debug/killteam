# 連線對戰

這個版本可放在既有靜態網站（包括子目錄）上，不需新增 Node.js 或資料庫。首頁按「連線對戰」；也可在進行中的對戰，從設定選單開啟連線。

配對方式和 Kahoot 一樣用房號：

1. 雙方開啟相同版本網站。房主按「建立房間」，畫面出現 6 位數房號。
2. 朋友按「連線對戰」，輸入房號後按「加入」。房主也可以按「複製邀請連結」傳給朋友，朋友打開連結就會自動加入，不用輸入。
3. 雙方看到「已連線」即可關閉視窗。連上之後房號就失效；斷線後請房主重新建立房間。
4. 房主設定兩隊與任務。按頂端「交給對方操作」可交接選隊、部署、移動、攻擊及擲骰選擇；訪客完成後按「交還房主」。等待時可按「請求操作」。

這是兩人共用一張棋盤的模式，雙方依桌遊流程手動交接操作權，未按 A／B 陣營自動限制可操作項目。連線時採用 2D 棋盤；部署請點選特工再點落點，裝備角度使用數值欄位。3D 模型頁與回放需結束連線後使用。原本的離線與單人模式保留。

## 網站更新

將更新後的 `index.html`、`online-board.html`、`sw.js`、`css/`、`js/` 上傳到現有 `killteam-main/` 目錄，保留原本的 `icons/`、`manifest.webmanifest`。雙方重新整理；若已安裝 PWA，也請關閉後重開。不可只上傳新的連線 JS，舊的 `main.js` 沒有連線入口。

網站需允許載入同目錄的 iframe 及 JavaScript；若伺服器另設 Content-Security-Policy，需允許同源 frame。`online-board.html` 自帶限制外部網路、表單與內嵌腳本的 CSP，訪客棋盤使用不具同源權限的 sandbox iframe。

## 房號配對服務

房號只用來交換雙方的 WebRTC 連線碼，交換完成就關閉；對戰資料仍由兩台裝置直接傳送，不經過配對服務。目前使用 PeerJS 的免費公共伺服器（`wss://0.peerjs.com/peerjs`，設定在 `js/online-signal.js` 的 `SIGNAL_SERVER`），網站本身不需要後端。公共伺服器沒有服務保證；連不上時，可改用「進階：手動交換連線碼」，流程和以前相同：房主建立邀請碼 → 訪客貼上並產生回覆碼 → 房主套用回覆碼。

- 房號是隨機 6 位數（不以 0 開頭）。若剛好被別人使用，會自動換一個。
- 一個房間只接受第一位加入者，其他人會看到「已經有人加入」。
- 打錯房號，或房主已關閉視窗，會顯示「找不到房號」。

### 將來連線組數變多時

目前組數少，用公共伺服器最省事。組數變多時，依序可以這樣處理：

1. **自架配對服務（幾十～幾百組同時）**：PeerJS 伺服器是開源的（npm 套件 `peer`），放在任何小型主機或雲端容器上，把 `SIGNAL_SERVER` 改成自己的網址即可，前端其他程式不用改。配對訊息很小，一台小主機就能撐住大量房間。
2. **無伺服器的房間服務（更多組，免維護主機）**：例如 Cloudflare Workers + Durable Objects，每個房號對應一個 Durable Object，只負責轉送兩份連線碼。同一套「OFFER／ANSWER 轉送」協定照用，可以自動擴充。到這一步也應該加上：
   - 同一 IP 嘗試房號的頻率限制，避免有人亂猜房號闖進別人的房間；必要時改成 8 位數或英數混合房號。
   - 房間逾時自動回收（例如 15 分鐘沒人加入就失效）。
3. **TURN 中繼**：約一到兩成的網路組合（公司防火牆、部分行動網路）無法直連，需要 TURN。組數多時，由上述配對服務發放短效 TURN 帳號（coturn 的 REST 憑證，或 Cloudflare／Twilio 等付費 TURN），玩家就不必自己填 TURN 帳號密碼。TURN 會轉送整場對戰的流量，是最主要的成本來源。
4. **更大規模或公開對戰**：需要大廳、配對排隊、斷線重連、觀戰時，再改成由伺服器保管對戰狀態（房主瀏覽器不再是唯一的運算來源），也才有辦法防止作弊。這是較大的改寫，等需求確定再做。

## 斷線與網路環境

- 房主是唯一的規則、擲骰及存檔來源，請保持分頁開啟。訪客不另跑遊戲引擎，不保存另一份對戰。訪客畫面使用房主的語言。
- 斷線時暫停遠端操作。房主可按「結束連線」繼續本機對戰，再從設定重新邀請。房主保持原分頁時，尚在處理的擲骰／選擇也保留；重新整理只可恢復一般自動存檔，不保證恢復尚未完成的對話框。
- 使用 WebRTC DataChannel 傳輸。預設向 Google STUN 查詢連線位址；某些公司、防火牆或行動網路無法直接連線，需要雙方在進階設定填入自己的 TURN 位址、帳號與密碼。未提供公共 TURN 服務，不能保證所有跨網路組合皆可直連。
- 邀請碼包含 WebRTC 連線資訊，只分享給一起遊玩的朋友。TURN 憑證不寫入存檔，也不放進邀請碼。
- 配對採房號（或手動的邀請碼／回覆碼），沒有公開大廳或永久房間。

參考：[WebRTC 連線與 offer/answer 交換](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Connectivity)。

## 驗證

`node tests/online.mjs` 測試房號格式、邀請碼種類／版本、訊息分段、Unicode、錯誤封包與傳送背壓。`node scripts/test.mjs` 包含這個測試。

有安裝 Playwright 與 Chromium 時可執行 `node scripts/test-online-browser.mjs`。也可設定 `PLAYWRIGHT_PATH` 指向 Playwright 的 `index.mjs`，以及 `CHROME_PATH` 指向 Chrome 或 Edge。另外安裝 npm 套件 `peer`（或以 `PEER_PATH` 指向它的 `dist/module.mjs`）時，測試會啟動本機 PeerJS 配對伺服器，改測房號流程：錯誤房號、邀請連結自動加入、連上後房號失效；沒有 `peer` 時則測手動連線碼。測試會啟動暫時的 localhost 伺服器及兩個隔離瀏覽器環境，以真正的 WebRTC 連線驗證設定、部署、擲骰、操作交接、過期指令與斷線；測試不依賴公共 STUN，不能代替外網與 TURN 的實機驗收。
